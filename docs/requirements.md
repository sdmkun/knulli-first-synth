# Brickシンセ 要件定義

tags: #wip #idea

## 概要
TrimUI Brick（Knulli）で動く、自作のシンセ兼シーケンサーの要件。そまくの頭の中のイメージを文章にしたもの（2026-10-30 初版）。
関連: [[TrimUI-Brick-アプリ開発]]（調査・開発環境）、[[作曲ツール作り]]

- 開発中: リポジトリ `E:\Documents\GitRepositories\knulli-first-synth`（git 未初期化）、PC の Claude Code セッション「TrimUI Brick synth for Knulli OS」（SDL2 + C++17）。2026-10-30 時点でフィルターエンベロープ・LFO・ディレイ・プリセット 9 種まで実装、PC で確認済み、実機は未確認
- このノートが要件の正本。リポジトリの `docs/requirements.md` はここからのコピー（2026-10-30 に配置）

### ひとことで
**楽器が弾けなくても、ボタンだけで「演奏っぽいこと」ができて、それがそのままループになって重なっていく、OP-1 みたいに触って楽しい箱。** 中身はグリッド（トラッカー）で、Renoise 的なノートコマンドやパターンのずらしで遊べる。グルーヴは後から外からかける。

### 優先度の付け方
- **必須（v1）**: これがないと「作りたいもの」にならない
- **推奨（v1.x）**: あるとかなり良くなる。v1 の設計で入る余地を残しておく
- **将来**: やりたいが後回し。設計で邪魔しない程度に意識する

## 詳細

### 1. ハードの前提と制約（TrimUI Brick）
| 項目 | 内容 | 設計への影響 |
|---|---|---|
| 画面 | 3.2 インチ、1024×768（4:3） | 小さいが高解像度。文字は大きめ、1 画面 1 用途。M8 風の文字ベース UI が合う |
| ボタン | 十字キー、A / B / X / Y、L1 / R1、L2 / R2、SELECT、START、MENU、背面 F1 / F2 | 鍵盤もパッドもない。**同時押しの組み合わせ**で操作を増やす（M8 方式）。アナログスティックはない |
| USB | USB-C が上下に 2 つ（そまく談） | Ableton の PC と USB-MIDI でつなぐ。Brick が USB デバイス側（MIDI 機器として PC に見える）になるのか、ホスト側で USB-MIDI IF を挟むのか、Knulli でどちらができるかは**要確認** |
| 音声 | 内蔵スピーカー、3.5 mm イヤホン端子、内蔵マイク（GrainBrick が録音に使用） | サンプリングは内蔵マイク or USB オーディオ IF から |
| CPU / RAM | Cortex-A53 × 4、1.8 GHz / 1 GB | 計算とメモリは十分。弱点は Linux のオーディオ経由の遅延と音切れ |
| OS | Knulli（Linux、SSH・SMB あり） | PORTS から起動。PC で書いて転送して実機確認 |

- 遅延の目標: ボタンを押してから音が出るまで **20 ms 以内**（演奏していて気にならない程度）。音の処理は専用スレッドで、UI とは分ける
- 電池で 2 時間以上は遊べること（CPU クロックを上げすぎない）

### 2. 全体の構成（イメージ）
- **トラック**: **4**（とりあえず十分。そまく）。1 トラック = 1 楽器（シンセ or サンプラー）＋ 1 パターン列
- **パターン**: グリッド（ステップ）でノートを置く。トラックごとに長さを変えられる（→ ポリリズム）
- **ソング**: なし。パターンのループと切り替えでパフォーマンスする
- **画面**: M8 のように、役割ごとの画面（ソング / パターン / 楽器 / ミキサー / プレイ）を十字キー＋修飾ボタンで移動する

### 3. 機能要件

#### 3-1. 同期（USB-MIDI）
- **必須**: USB-MIDI クロックの**受信**（Brick は子、親は PC の Ableton）。Start / Stop / Continue に追従、ソングポジションポインターにも対応
- **必須**: 内部クロックでも単体で動く（BPM 設定、タップテンポ）
- **将来**: MIDI クロックの送信（Brick が親）。いまは不要（そまく）
- **将来**: MIDI ノートの入力（外部キーボードで弾く）。外部機材を鳴らす（ノート出力）は**やらない**（そまく）
- **将来**: Ableton Link（Wi-Fi）

#### 3-2. ループ再生 / 無限再生
- **必須**: パターンをループ再生し続ける。再生中に編集でき、止めずに反映される
- **必須**: トラックごとのミュート / ソロ
- **推奨**: パターンの切り替えを次の小節の頭で予約（ライブ的に展開を作る）
- **将来**: プロシージャル再生。ルール（確率・スケール・リズムの密度）から無限にフレーズを生み続けるモード（GrainBrick の ORBIX のようなもの）。気に入った部分を「パターンとして確定」できる

#### 3-3. オーバーダブ録音
- **必須**: ループ再生中に演奏したノートを、ループを止めずにパターンへ重ねて記録する
- **必須**: 記録は**クオンタイズしてグリッドに置く**（タイミングのずれは捨てる。グルーヴは後で 3-8 で付ける）
- **必須**: 直前の録音を取り消す（アンドゥ）。オーバーダブ 1 周ぶん単位
- **推奨**: 録音前のカウントイン、メトロノームのオンオフ
- **推奨**: 置き換え録音（重ねずに上書き）との切り替え
- **やらない**: オーディオのルーパー（録った音を重ねる）。ループはノートデータのみ（そまく）

#### 3-4. 音作り
- **必須**: 減算シンセ 1 種（オシレーター → フィルター → アンプ、エンベロープ、LFO）。※ 開発中のアプリで大部分は実装済み
- **必須**: プリセットの読み書き。最初から「すぐ使える音」が入っている（ベース・リード・パッド・ドラム系）
- **必須**: ドラムが鳴らせる。**サンプル**で鳴らす（まずワンショット、のちにスライス。3-9）。リズムがないと「演奏っぽさ」が出ない
- **推奨**: トラックごとのエフェクト（ディレイ・リバーブ・ディストーション）、全体のマスターエフェクト
- **推奨**: 「ランダムに音を作る」ボタン（OP-1 的な遊び）
- **将来**: ほかのエンジン（FM、ウェーブテーブル、グラニュラー）

#### 3-5. M8 風のパラメータ操作
- **必須**: 編集ボタン（例: A）を押しながら十字キーで値を変える
  - 左右: ±1（細かく）
  - 上下: ±10（大きく）。ノートなら ±1 オクターブ、ステップ数なら ±4 / ±16 など、**値の種類ごとに意味のある単位**にする
- **必須**: 修飾ボタン（例: SELECT / L / R）＋十字キーで画面移動・範囲選択・コピー＆ペースト
- **必須**: 値の初期化・削除のショートカット（M8 の「B + A」のようなもの）
- **推奨**: 割り当て一覧を画面に出せる（覚えなくていい）。キー設定ファイルで変えられる
- 操作の割り当ての細部は、実機で触りながら決める

#### 3-6. 演奏できない人でも演奏っぽく（プレイモード）
- **必須**: **スケールロック**。キー（C、D♯ など）とスケール（メジャー、マイナー、ペンタトニック、ドリアン…）を選ぶと、ボタンにはそのスケールの音だけが割り当たる。外れた音は出ない
- **必須**: ボタン配置: 十字キー＋ABXY の 8 ボタンにスケールの 8 音（1 オクターブ）、L / R でオクターブ上下
- **必須**: プレイモードで弾いたものがそのまま 3-3 のオーバーダブ録音になる
- **推奨**: コードモード。1 ボタンでスケール内のコード（I、IV、V、vi…）が鳴る
- **推奨**: アルペジエーター（ボタンを押している間、コードの音を順に鳴らす）
- **推奨**: 「ノートリピート / ロール」（押している間 1/8、1/16 で連打）。ドラムに効く
- **将来**: 音楽理論の知識なしで選べる「雰囲気」プリセット（「切ない」「明るい」「和風」→ キーとスケールとコード候補が決まる）

#### 3-7. グリッド＋ノートコマンド＋パターン制御（Renoise 的な要素）
基本は「グリッドに沿って置く。演奏はクオンタイズする。揺れは外から足す」。
- **必須**: グリッド編集。ステップの解像度（1/16 など）、ノート・ベロシティ・長さ
- **必須**: トラックごとにパターンの長さを変えられる（例: 16 と 12 と 7 を同時に回す → ポリリズム / ポリメーター）
- **推奨**: ノートごとのコマンド（Renoise のエフェクトコマンドのイメージ）。表示は**アイコン＋名前**、狭いところはアイコンだけ（16 進コードは使わない）。候補:
  - ディレイ（ステップ内で少し後ろにずらす）、リトリガー（ステップ内で連打）、確率（鳴る / 鳴らない）、ベロシティのランダム、ピッチスライド、パラメータの一時変更、カット
- **推奨**: パターンの再生方向（逆再生・ピンポン・ランダム）、トラックごとの再生速度（×2、×1/2、×3/4 など）
- **将来**: 条件付きトリガー（「4 回に 1 回だけ鳴る」など。Elektron の Trig Condition 的なもの）、ユークリッドリズムの自動生成

#### 3-8. グルーヴ（外から与えるタイミングの揺れ）
- **必須**: スウィング量（1 つのつまみで、裏拍を後ろにずらす）。トラックごとに効かせる / 効かせないを選べる
- **推奨**: グルーヴテンプレート。ステップごとのタイミング・ベロシティのずれをまとめたもの。いくつか内蔵（MPC 風スウィング、レイドバック、ハネ）
- **推奨**: **レイドバック**: トラック全体をわずかに後ろにずらす（ms 単位 or ステップの何 % か）。ベースやスネアを遅らせて「タメ」を出す
- **推奨**: グルーヴの量（0〜100 %）をあとから変えられる。ノートのデータ自体は書き換えない（**非破壊**）
- **将来（低優先度）**: Ableton のグルーヴファイル（`.agr`）の読み込み。中身は XML で、基準になる MIDI のタイミング・ベロシティと、Timing / Random / Velocity の量。これを内部のグルーヴテンプレートに変換する

#### 3-9. サンプリング / オーディオの取り込み
- **必須**: WAV ファイルの読み込み（SD カード / SMB で置いたもの）。録音より先にやる（そまく）
- **必須**: 読み込んだ音をサンプラー楽器として鳴らす（まずワンショット。ピッチを変えて鳴らす）。開始・終了位置の調整
- **推奨**: 内蔵マイク / USB オーディオ IF からの録音
- **推奨**: スライス（ブレイクを等分 or 音の頭で切り、ステップに並べる）。ジャングル / ブレイクコア用途
- **将来**: タイムストレッチ、グラニュラー再生

#### 3-10. OP-1 のような楽しさ
要件というより、判断に迷ったときの指針。
- 電源を入れたら**すぐ音が出せる**（起動して数秒でプレイモード、前回の状態から再開）
- 操作に**目に見える反応**がある（音に合わせて動くアニメーション、パラメータが絵で見える）
- 制約は悪ではない（トラック数・長さに上限があってよい。かわりに迷わない）
- 失敗してもすぐ戻せる（アンドゥ、自動保存）
- **ランダム・偶然**で遊べる要素がある（ランダム音作り、確率ノート）
- 画面の雰囲気: **M8 と OP-1 のいいとこどり**（そまく）。情報が詰まる画面（パターン・楽器のパラメータ）は M8 のように文字を多く、プレイモードや状態の表示は OP-1 のようにアニメーションや絵で

#### 3-11. 保存・書き出し
- **必須**: プロジェクトの保存 / 読み込み（自動保存あり）
- **推奨（v1.x で最優先）**: **ステムの書き出し**。トラックごとの WAV をレンダリングして DAW（Ableton）に持っていく。曲を仕上げるのは DAW、という流れ（そまく）
- **推奨**: パターンを MIDI ファイル（`.mid`）で書き出す
- **やらない**: ソング機能（パターンを並べて曲にする）。本体ではパフォーマンスとしての再生だけ（そまく）

### 4. 非機能要件
- **安定性**: 1 時間ループさせても音切れ・ズレがない。MIDI クロック追従時のテンポのブレは ±1 ms 程度
- **応答**: ボタン → 音 20 ms 以内。画面は 30 fps 以上
- **PC で動く**: 同じコードが Windows でも動き、音作り・画面の調整は PC で詰められる（今の開発方式を維持）
- **データ形式**: プロジェクトは人が読めるテキスト形式（JSON など）。Claude や PC から中身をいじれる

### 5. 段階リリース案
1. **v0.x（いま）**: シンセ 1 種＋プリセット（ほぼ済み）→ 実機で音が出るか確認
2. **v1**: プレイモード（スケールロック）＋ループ＋オーバーダブ録音＋グリッド編集（4 トラック）＋ドラム（WAV のワンショット）＋スウィング＋MIDI クロック受信＋保存
3. **v1.x**: ステム書き出し、ノートコマンド、トラックごとのパターン長・速度、グルーヴテンプレート / レイドバック、コード・アルペジエーター、スライス、エフェクト
4. **将来**: プロシージャル再生、.agr 読み込み、録音（マイク / USB IF）、グラニュラー、Ableton Link

### 6. 決まったこと（2026-10-30 そまくの回答）
- 同期: Brick は子、Ableton が親
- 外部機材は鳴らさない
- トラックは 4 で十分
- オーディオのルーパーは不要（ループはノートデータ）
- プロシージャル再生は将来でいい
- サンプルはファイル読み込みが先。ドラムはサンプル（まずワンショット、できればスライスも）
- ノートコマンドはアイコン＋名前（狭ければアイコンのみ）
- 画面は M8 と OP-1 のいいとこどり。情報が詰まるところは文字多め
- ソング機能は不要。本体ではパフォーマンス再生、仕上げはステムを書き出して DAW で
- OS: 主流で、オーディオに強い OS があればそちらを優先

#### OS のメモ（2026-10-30 時点）
- Brick 向けの主な選択肢は **Knulli**（Batocera ベース、ふつうの Linux。SSH あり）と **NextUI**（純正ファームの上に載る軽い OS）
- オーディオ向けを名乗る Brick 用 OS は見当たらない。音楽アプリの実績は Knulli（GrainBrick、Python）と NextUI（Trimpod などの音楽プレーヤー Pak）の両方にある
- MIDI に必要なのは Linux カーネルの USB-MIDI（snd-usb-audio）と ALSA の MIDI（ALSA sequencer / rawmidi）。どちらの OS で有効かは未確認。Knulli は一般的な Linux に近いぶん、ここが通っている可能性が高そう
- いまのところの判断: **Knulli のまま進める**。今のアプリ（SDL2 + C++17）も Knulli 向けに作ってあり、MIDI が通らないとわかったら乗り換えを検討する
